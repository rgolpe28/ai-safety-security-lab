Common privacy risks

Tap a card to expand it.

Unnecessary collection

More data means more exposure.

Use data minimization: collect only what is required for the task and avoid copying entire records into prompts.

Prompt leakage

Sensitive details may be passed into prompts or logs.

Redact or tokenize identifiers before sending data to a model where full identity is not needed.

Over-broad retrieval

RAG systems may return records a user should not see.

Enforce record-level authorization before retrieval. The model should not decide access rights by itself.

Long retention

Old prompts and logs can become a privacy liability.

Set retention limits and securely delete data that is no longer required.

Key principle

Privacy controls should be part of AI security architecture, not treated only as a compliance task.

Defense in depth

Use multiple controls: minimization, authorization, redaction, least privilege, output checks, logging controls, and human review.

Responsible testing

Use synthetic data and authorized environments. Avoid exposing real personal information during experiments.
